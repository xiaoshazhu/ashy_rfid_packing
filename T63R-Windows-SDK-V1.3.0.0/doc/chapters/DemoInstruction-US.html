1、Software system environment

  1. This demo supports Windows and Linux systems. For Windows, it requires a system of Windows XP or above. Its main purpose is template editing.
  2. If you need to print a PDF, you can configure it in the sdkcfg.xml file. Currently, we support two forms of PDF printing. For internal logical processing of the PDF, set it to "0" in the sdkcfg.xml file. If you need a PDF plugin, you need to configure the plugin path first.

2、Operation Instructions

Windows：

  1. Unzip the compressed package (the version will be continuously upgraded, and the specific name shall be subject to the actual situation).
  2. After unzipping, Select and enter the folder of the corresponding architecture system development kit.
  3. After unzipping, enter the bin\Win32 or bin\x64 folder.
  4. Finally, double - click DSTP2xDemo.exe to run it.

Linux：

  1. Unzip the compressed package (the version will be continuously upgraded, and the specific name shall be subject to the actual situation).
  2. After unzipping, select and enter the folder of the development package for the corresponding architecture system.
  3. After unzipping, enter the bin folder.
  4. Right-click in the blank area and select "Open Terminal".
  5. Enter the command: sudo su, enter the password to switch to the root user. If the permission is insufficient, enter chmod -R 777 * and then execute.
  6. Enter the command to run:./map.ds, which is used to grant permission to run the program based on the SDK to control the printer connected via USB.
  7. Enter the command to run:./DSTP2xDemo.out.

3、DSTP2xDemo Function introduction

3.1、Introduction to template functions

3.1.1、Overview

The startup interface is shown in Figure 1.1. The startup interface includes template selection, template editing, template parameter input settings, clearing the output information in the output box, the printing function, and the real-time return of the printer status, etc.

3.1.2、Connect the device

Click in the upper - left corner to enter the device connection selection and choose [Enumerate/Connect to the printer]. Connect according to the actual emulation type of the printer and the required connection method.

  1. Emulation selection: This refers to the printing language that the printer can recognize. Select the corresponding emulation type according to the printer settings. Currently, ZPL, TSPL, and ESCPOS are supported. You can print a self-check page to confirm the current emulation type of the machine.
  2. Printer connection method: Select the corresponding connection according to the actual application scenario. Currently, USB enumeration, network port enumeration within the same network segment, IP direct connection, and serial port direct connection are supported.

3.1.3、Select a preset template or edit a new template on your own.


  1. Preset template: A pre-edited template in the default path. After selection, you can view the relevant parameter attributes.
  2. New template: Create a blank template and add elements for editing according to the actual printing requirements.
  3. Save template: Save the template that is currently being edited.
  4. Save template as: Save the currently edited template to a specified directory.
  5. Open preset template path: The default directory where the printing demo stores the templates.
  6. Open log path: Open the interface call log for analysis. Generally, the default path is: C:\Users\username\AppData\Local\Temp\DSSDKTemp\ThermalLog.

3.1.4、Edit the printing and RFID content according to the actual needs.


  1. The Label tree diagram on the left side: Displays all the printing elements and RFID data editing within the current template.
  2. The middle part is the template preview. After editing the parameters, you need to press the Enter key or click on other parameters to refresh the preview.
  3. The right side is for setting the parameter attributes of specific elements, which should be edited according to the actual printing requirements.

3.1.5、After editing the template, select the number of printing loops and click to start printing.


  1. Read TID/EPC first: After checking this option, the corresponding data will be returned first, and then the printing will be executed (Currently, it does not support checking both options to return data simultaneously).
  2. Image DPI: Set it to the actual DPI of the printer print head (Currently, the machines have 203dpi, 300dpi, and 600dpi) and convert it to the corresponding printing size.

3.2、Introduction to Other Functions

The other function interfaces are shown in Figure 1.2, including common acquisition functions, RFID functions, PDF printing, and direct data transmission functions. All operations need to be performed after connecting the device.

(1) Common Functions

  1. Ordinary Positioning Label: Position and verify ordinary labels or black mark paper.
  2. Print Self-check Page: Click to print the self-check page information of the printer.
  3. Clear Printer Cache: Click to clear the printer cache, and it will return to the data-free state without the need to restart.
  4. Get Version Number: Obtain the firmware version information of the currently connected machine.
  5. Get Manufacturer Model: Obtain the manufacturer and model information of the currently connected machine.
  6. Get Machine Number: Obtain the machine number information of the currently connected machine.
  7. Immediate Paper Cutting: Used to control the machine's paper cutting template, and the paper cutting action will be executed immediately after the operation; (The machine needs to be equipped with a paper cutter module).
  8. Turn on the Paper Cutter: Enable the paper cutter function of the printer.
  9. Turn off the Paper Cutter: Disable the paper cutter function of the printer.

((2) RFID Functions

  1. RFID Label: Position and verify the RFID label [The machine will feed the paper slowly, so please be patient and wait for the positioning to be completed].
  2. Read EPC: Directly read the EPC data of the current label.
  3. Read TID: Directly read the TID data of the current label.
  4. Get Writing Power: Obtain the writing power of the currently connected machine.
  5. Get Reading Power: Obtain the reading power of the currently connected machine.
  6. Set Writing Power: Manually set the writing power of the currently connected machine [The most suitable value will be automatically detected during positioning verification. There is no need to modify it unless necessary].
  7. Set Reading Power: Manually set the reading power of the currently connected machine [The most suitable value will be automatically detected during positioning verification. There is no need to modify it unless necessary].

(3) PDF Printing

  1. Input values for the printing offset position, width, height, and rotation angle according to the actual printing size.
  2. Write RFID Data: If you need to write data during printing, check the option, and a data input box will be displayed. Then, input the data you need to write.
  3. Select a PDF file, input the printing page number, and then print.
    If you need to print a PDF, you can configure it in the sdkcfg.xml file. Currently, two forms of PDF printing are supported. For internal logical processing of the PDF, set it to "0" in the sdkcfg.xml file. If you need a PDF plugin, you need to configure the plugin path first.

(4) Direct Data Transmission

  1. It is used to directly transmit data files for printing.

4.2.6、Add Table

Right-click on "print" with the mouse -> Click on "Add Table".


Modify the table attribute parameters.

The default table has 1 row and 1 column. In the table attribute column on the right side, you can modify the coordinates, width and height, number of rows and columns, position of row and column boundary lines, etc. of the table.
In the tree-shaped navigation bar on the left side, each Bcell corresponds to a cell. The initial width and height of each cell are evenly divided according to the total width and height of the table and the number of rows and columns.



Adjust the row height of the table.

You can adjust the row height accordingly by adjusting the row boundary line.

Row boundary line: In the table, each horizontal line is defined as a row boundary line. Counting down from the top horizontal line of the table: row boundary line 0, row boundary line 1, row boundary line 2... The y-coordinate of the table restricts row boundary line 0. Therefore, the adjustment of the row boundary line can only start from row boundary line 1.

Adjusting the row height: Adjust the row height through the row boundary line. If the row height of a certain row decreases, the entire table will move upward, and if it increases, the entire table will move downward.


Increase the line boundary by 2mm, increase the overall height of the entire table by 2mm, and move the whole table downward.


The handle of the label canvas returned by the DSTP2x_CreateLabelContext function.

You can adjust the column width accordingly by adjusting the column boundary line.

Column boundary line: In a table, each vertical line is defined as a column boundary line. Counting from the leftmost vertical line of the table to the right: column boundary line 0, column boundary line 1, column boundary line 2, and so on. The x-coordinate of the table restricts column boundary line 0. Therefore, the adjustment of the column boundary line can only start from column boundary line 1.

Adjusting the column width: By adjusting a certain column boundary line, the column widths of the two adjacent cells of this column boundary line show a relationship of one decreasing while the other increasing. For example, for a table with 5 rows and 3 columns, if column boundary line 1 is adjusted to increase by 5mm, then the width of the first column will increase by 5mm, and the width of the second column will decrease by 5mm correspondingly, and the width of the third column will remain unchanged. If the rightmost column boundary line 3 of this table is adjusted, then only the width of the third column will be affected. When column boundary line 3 increases, the table will extend to the right, and when column boundary line 3 decreases, the table will shrink to the left.

4.2.7、Add RFID to the label

Add EPC

Right-click on "RFID" in the label template navigation bar on the left side and select "Add EPC".

Data types: There are two types, HexStr and ASCII.

Epc Data Writing Rules:
① The written EPC data must be an integer multiple of 2 bytes in length.
For the ASCII type, one number occupies one byte. Therefore, the length of the data written in the ASCII type needs to be an integer multiple of 2.
Example:
ASCII: 1234abcd. The data actually written into the label chip is: 31 32 33 34 61 62 63 64 (because in the ASCII mode, it will be converted into the hexadecimal data corresponding to the ASCII code table before being written).
For the HexStr type, 2 numbers occupy one byte. Therefore, the length of the data written in the HexStr type needs to be an integer multiple of 4.
Example:
HexStr: 1234abcd. The data actually written into the label chip is: 12 34 ab cd.
② The length of the EPC cannot exceed the specifications of the label chip. For example, if the specification of the label chip is 96 bits, then the EPC can only be written with 96/8 = 12 bytes. If the length exceeds this limit, it cannot be written. With HexStr, 24 numbers can be written, and with the ASCII method, only 12 numbers can be written.
③ The ASCII type can write any character data in the ASCII code table, while the HexStr type can only write numbers from 0-9 and letters from a-f.
Read and Write Modes: There are three modes: WR, W, and R.
WR: The process is: write EPC - print - read EPC.
W: The process is: write EPC - print.
R: The process is: print - only read EPC.

Add USER

Right-click on "RFID" in the label template navigation bar on the left side and select "Add USER".

Data types: There are two types, HexStr and ASCII.
USER Data Writing Rules:
① The written USER data must be an integer multiple of 2 bytes in length.
For the ASCII type, one number occupies one byte. Therefore, the length of the data written in the ASCII type needs to be an integer multiple of 2.
Example:
ASCII: 1234abcd. The data actually written into the label chip is: 31 32 33 34 61 62 63 64 (because in the ASCII mode, it will be converted into the hexadecimal data corresponding to the ASCII code table before being written).
For the HexStr type, 2 numbers occupy one byte. Therefore, the length of the data written in the HexStr type needs to be an integer multiple of 4.
Example:
HexStr: 1234abcd. The data actually written into the label chip is: 12 34 ab cd.
② The length of the USER cannot exceed the specifications of the label chip. For example, if the specification of the label chip is 96 bits, then the USER can only be written with 96/8 = 12 bytes. If the length exceeds this limit, it cannot be written. With HexStr, 24 numbers can be written, and with the ASCII method, only 12 numbers can be written.
③ The ASCII type can write any character data in the ASCII code table, while the HexStr type can only write numbers from 0-9 and letters from a-f.
Read and Write Modes: There are three modes: WR, W, and R.
WR: The process is: write USER - print - read USER.

4.2.9、Drag and scale the template preview image.

When the content in the preview image is unclear or not fully displayed, you can scale, drag and move the preview image.
Scaling: Place the mouse cursor over the content you want to enlarge, and scroll the mouse wheel (or move the cursor above the preview image) to scale it.
Dragging: Hold down the left mouse button on the preview image, and you can drag it to move it up, down, left, or right.
